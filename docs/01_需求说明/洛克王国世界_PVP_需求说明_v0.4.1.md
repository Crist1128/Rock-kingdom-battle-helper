# 洛克王国世界 PVP 需求说明 v0.5

> 更新时间：2026-06-09
> 当前方向：实时面板估计、默认配置校验、事件 evidence 和事件流重放。旧候选空间生成、候选筛选和候选硬排除方案已经废弃并从代码中清理。

## 1. 核心目标

系统用于本地 PVP 战斗辅助记录和敌方面板反推：

1. 录入己方配置和敌方精灵阵容。
2. 手动记录战斗事实：伤害、资源、状态、切换、技能事件和回合结束。
3. 根据 observation 实时维护敌方 HP、攻防、速度等属性约束。
4. 展示默认配置面板、当前估计范围、unknown factors 和 evidence。
5. 支持事件作废、修正和从指定事件重放估计层。
6. 支持 BWIKI 静态数据爬取、清洗、dry-run 和导入。

## 2. 非目标

- 不自动识图。
- 不自动推荐出招。
- 不在前端伪造伤害公式或速度概率。
- 不恢复准备阶段生成候选空间。
- 不把未知公式或未知状态强行当作确定事实。

## 3. 推算方式

敌方真实配置未知时，玩家先选择一个默认配置用于展示。随着战斗事实录入，后端把观察事件转成实时约束：

- 敌方受到攻击：推导 HP、物防或魔防范围。
- 敌方造成伤害：推导物攻或魔攻范围。
- 技能出现：记录技能事实，供后续伤害上下文使用。
- 速度先后手：先记录不等式和 unknown factors，后续扩展概率解释。

推导结果写入 `EnemyPanelEstimate` 和 `EnemyPanelEstimateEvidence`。约束冲突时记录 conflict，不直接覆盖为某个固定配置。

## 4. 数据与导入

静态规则来自本地数据库和 rocom BWIKI 数据管线：

- 精灵定义；
- 技能定义；
- 精灵可学习技能；
- 性格规则；
- 属性克制规则；
- 状态定义和技能结构化操作。

数据导入必须支持 dry-run、摘要、错误列表和 commit 边界。

## 5. 后续重点

1. 完整应对/防御结算。
2. 天气、状态、技能槽 modifier 对公式和反推的影响。
3. 速度约束和先后手解释。
4. 状态实例、自动结算副作用和快照链重放。
5. 估计 evidence 的完整解释页。
