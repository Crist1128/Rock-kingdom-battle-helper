# 技能规则执行能力审计 v0.1

更新日期：2026-06-12

本文用于对照“已导入的技能规则 JSON”和“当前前后端实际执行链”，避免把仅保留接口的机制误认为已经自动生效。

## 1. 当前审计入口

- 后端接口：`GET /api/v1/skills/capability-audit`
- 前端入口：规则库页面新增“规则能力审计”标签页。
- 审计方式：扫描当前 `skill_definition` 中的 `damage_rule_json.manual_review.future_hooks` 与 `effect_operations_json`，按执行器支持情况拆分为“已有执行链”和“仍保留接口”。

## 6. 审计结论

当前已导入的可执行 `effect_operations_json` 没有发现未知 `op_type`，但大量 `future_hooks` 仍是“保留接口”。前端已提供审计页，后续每次批量导入或手工规则录入后，应先看审计页是否出现新的 `unsupported_operation_counts` 或高风险保留 hook，再决定是否进入代码落地。

## 7. 2026-07-05 复杂分支第二轮落地

本轮按人工审阅确认，先避开传动、技能槽位置、变形/复制、奉献和强制换人，新增 20 个复杂分支的执行能力或 seed 规则：

- 条件连击：后手、生命低于 50%、本回合敌方换人、按星陨印记层数动态加连击。
- 动态威力：先手、换人、冻结存在、印记层数、已损生命、敌方能量、上一回合成功应对。
- 伤害后效果：击败后回能、击败后加魔攻、击败后中毒转中毒印记、按伤害吸血。
- 状态操作：按极性驱散正面增益、立即触发一次指定状态伤害。
- 动态能耗：`毒液渗透` 按敌方中毒层数与中毒印记层数合计，每层能耗 `-1`。

新增可执行 `op_type`：

| op_type | 用途 |
| --- | --- |
| `convert_effect` | 将目标身上的一个状态转换为另一个状态，默认继承层数 |
| `trigger_status_damage_now` | 立即结算目标身上指定状态的一次状态伤害 |

当前 seed 统计：`structured` 275 条，`partial` 163 条，`needs_review` 57 条，`ambiguous` 1 条。
