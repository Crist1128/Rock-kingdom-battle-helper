# 独立伤害计算器设计 v0.1

> 日期：2026-07-07
> 范围：P0/P1 最小可用版本；独立于战斗工作台，不参与当前战斗事件流。

## 1. 目标

独立伤害计算器用于实战中快速估算一次技能伤害，支持两种使用方式：

1. 从最近一场战斗只读导入己方/敌方阵容、面板和技能摘要；
2. 完全手动搜索攻击方精灵、防御方精灵和技能；
3. 手动配置双方性格与个体资质，或直接使用导入面板；
4. 填写天气、威力、能力倍率、减伤、连击等临时修正；
5. 查看理论伤害、血量百分比、解释链、未知因素和缺失上下文；
6. 可录入真实伤害做偏差展示，为后续 P2 敌方配置枚举反推预留入口。

## 2. 边界

P0/P1 明确不做以下事情：

1. 不创建 `BattleEvent` / `DamageEvent`；
2. 不修改 `BattleElfState`、`BattleEffectInstance`、`BattleSkillSlot`；
3. 不创建或回写 `BattleEffectSnapshot`；
4. 不写入 `EnemyPanelEstimate` 或 evidence；
5. 不改变战斗工作台当前状态；
6. 不把真实伤害直接用于候选硬排除或敌方配置落库。

## 3. P0/P1 能力分层

| 阶段 | 能力 |
|---|---|
| P0 | 手动选择双方精灵、性格、资质、技能，计算理论伤害 |
| P0 | 手动填写天气/威力/能力/减伤/连击等修正项 |
| P1 | 只读读取最近战斗的阵容、面板、技能摘要用于快捷填充 |
| P1 | 支持录入真实伤害并展示与理论值的偏差 |
| P2 | 根据真实伤害枚举反推敌方配置，默认仍不污染战斗推算 |

## 4. 后端设计

新增模块：

- `backend/app/schemas/damage_calculator.py`
- `backend/app/services/standalone_damage_service.py`
- `backend/app/api/v1/endpoints/damage_calculator.py`

新增 API：

### `GET /api/v1/damage-calculator/bootstrap`

返回最近一场未软删除战斗的只读摘要：

- battle 基本信息；
- self/enemy 阵容；
- 每只精灵当前面板、性格、个体资质、技能 ID 列表；
- 没有战斗时返回 `latest_battle: null`。

### `POST /api/v1/damage-calculator/calculate`

请求包含：

- 攻击方输入；
- 防御方输入；
- 技能 ID；
- 修正项；
- 可选真实伤害。

后端流程：

1. 校验精灵、性格、技能是否存在；
2. 有手动面板时直接使用面板；
3. 无手动面板时复用 `StatCalculator` 根据性格和资质计算面板；
4. 构造 `DamageFormulaContext`；
5. 复用 `RuleResolver` 解析本系、克制、连击、技能规则和手动修正；
6. 复用 `DamageCalculator` 计算理论伤害；
7. 返回解释链、未知因素、缺失上下文和真实伤害偏差。

### `POST /api/v1/damage-calculator/infer-defender`

根据真实伤害返回防御方配置软候选。P2 最小版采用保守枚举：

1. 固定攻击方、技能和本次修正项；
2. 固定防御方精灵种类；
3. 枚举全部性格；
4. 枚举 HP 资质 `0-10`；
5. 根据技能类别只枚举本次相关防御资质：
   - 物理技能枚举物防资质；
   - 魔法技能枚举魔防资质；
6. 其它资质不参与本次伤害判断，输出中按 0 展示；
7. 复用正向伤害计算链得到每个候选的理论伤害；
8. 按与真实伤害的绝对偏差排序。

该接口仍然不写入 `EnemyPanelEstimate`，也不作为候选硬排除依据。

## 5. 前端设计

新增页面：

- 路由：`/damage-calculator`
- 页面：`frontend/src/pages/DamageCalculatorPage.tsx`
- 导航：`伤害计算器`

页面区域：

1. 最近战斗快捷导入区；
2. 攻击方配置卡；
3. 防御方配置卡；
4. 技能搜索与技能描述；
5. 修正项输入；
6. 真实伤害输入；
7. 结果卡，包括理论伤害、百分比、未知因素、解释链 JSON。
8. 真实伤害反推按钮和防御方候选列表。

## 6. 风险控制

- 该功能是独立只读工具，不会污染战斗工作台事件流。
- 真实伤害可用于独立计算器中的软候选排序，但不生成敌方配置推算落库。
- 手动修正优先；未填写的项目交给现有规则解析链处理。
- 不新增数据库表和 Alembic 迁移。

## 7. 后续 P2 方向

后续可以继续扩展：

1. 支持枚举更多资质模板，例如速度/双抗/主攻线；
2. 支持按多次真实伤害合并评分；
3. 支持把独立候选导出为“待确认配置”，但必须由用户显式确认后才允许写入战斗推算。

## 8. P2.2 累计样本与默认模板模式

本轮补充 P2.2，仍然保持独立只读：

1. 单次反推新增 `candidate_mode`：
   - `focused`：只枚举 HP 与本次伤害直接相关的物防/魔防资质，适合快速缩小防御线；
   - `default_templates`：按常见默认资质模板补齐三维资质，例如生命+速度+物攻、生命+速度+魔攻、生命+双防等，适合贴近默认配置查看。
2. 新增多样本累计反推接口 `POST /api/v1/damage-calculator/infer-defender-batch`：
   - 所有样本共享同一个防御方精灵与同一个候选防御方配置；
   - 每条样本可以有不同攻击方、技能、真实伤害和手动修正项；
   - 对每个候选累计所有样本的绝对偏差 `total_absolute_delta`，并按总偏差、命中样本数和匹配分排序；
   - 返回逐条样本的预测伤害、偏差、是否命中容忍范围。
3. 前端累计样本逻辑：
   - 用户先按当前表单填写攻击方、技能、修正项和真实伤害，再点击“加入累计样本”；
   - “累计反推”使用当前防御方精灵与已累计样本进行联合排序；
   - “清空累计/新开计算”会清空样本和累计结果，不影响当前单次表单，方便重新开始一轮计算；
   - 单次反推与累计反推都不会写入战斗事件、状态、快照、EnemyPanelEstimate 或 evidence。

限制：P2.2 仍然是软候选排序，不做硬排除；如果公式链返回 unknown factors，需要由用户结合实战语境判断结果可信度。

## 9. 前端交互补充

2026-07-07 补充：

1. 最近战斗快捷导入改为下拉选择，避免阵容较多时占用过多页面空间。
2. 攻击方/防御方卡片显示精灵头像，并支持从已保存的己方配置中导入性格、资质和技能配置摘要。
3. 性格选择会按“性格 → 默认资质模板”预填资质；资质输入改为下拉选择“不点/7/8/9/10”，并保留“按当前性格重置资质”按钮。
4. 右侧结果区拆成“单纯计算伤害”和“反推防御方”两个模式，真实伤害只在反推模式中填写。
5. 初始化响应额外返回属性克制规则，前端按当前攻击方、技能和防御方系别预填本系倍率与克制倍率；真正计算仍以后端 `RuleResolver` 为准。
6. 减伤列表 UI 使用百分比输入，例如 `90%, 75%`，前端提交前转换为公式所需的小数比例。

2026-07-07 继续调整：

1. 主界面不再把“能力倍率、额外倍率”作为常规输入项展示；这些属于公式底层覆盖字段，仅保留在“高级公式覆盖”折叠区。
2. 常规输入改为状态类层数：
   - 攻击方当前攻击属性增加/降低层数；
   - 防御方当前防御属性增加/降低层数；
   - 技能威力增加/降低层数。
3. 状态层数换算沿用现有状态定义：
   - 属性增减每层按 `10%`；
   - 技能威力每层按 `10` 点威力。
4. 减伤比例输入显示固定 `%` 后缀，用户只填写数字，例如 `90, 75`；前端提交前转换为 `0.9, 0.75`。
