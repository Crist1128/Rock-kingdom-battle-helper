# 独立伤害计算器设计 v0.1

> 日期：2026-07-07
> 范围：独立于战斗工作台，只读复用静态数据、最近战斗阵容和已保存配置，不参与当前战斗事件流。

## 1. 目标

独立伤害计算器用于实战中快速估算一次技能伤害，并在敌方受击后按血量百分比反推可能的 HP 与防御配置。

核心目标：

1. 可从最近一场战斗只读导入己方/敌方阵容、面板和技能摘要；
2. 可完全手动搜索攻击方精灵、防御方精灵和技能；
3. 可配置双方性格与资质，或直接使用导入面板；
4. 可填写天气、属性层数、技能威力层数、减伤、连击等临时修正；
5. 可查看理论伤害、扣血百分比、解释链、未知因素和缺失上下文；
6. 可根据敌方受击前后生命百分比进行一次性软反推，输出可能的 HP 资质、防御性格和防御资质。

## 2. 边界

该功能是独立只读工具，明确不做：

1. 不创建 `BattleEvent` / `DamageEvent`；
2. 不修改 `BattleElfState`、`BattleEffectInstance`、`BattleSkillSlot`；
3. 不创建或回写 `BattleEffectSnapshot`；
4. 不写入 `EnemyPanelEstimate` 或 evidence；
5. 不改变战斗工作台当前状态；
6. 不把反推结果作为候选硬排除依据。

## 3. 后端接口

新增模块：

- `backend/app/schemas/damage_calculator.py`
- `backend/app/services/standalone_damage_service.py`
- `backend/app/api/v1/endpoints/damage_calculator.py`

接口：

1. `GET /api/v1/damage-calculator/bootstrap`
   - 返回最近一场未删除战斗的只读摘要；
   - 包含 self/enemy 阵容、当前面板、性格、个体资质、技能 ID 列表；
   - 同时返回属性克制规则，供前端预填克制倍率。
2. `POST /api/v1/damage-calculator/calculate`
   - 根据攻击方、防御方、技能和修正项计算理论伤害；
   - 可选 `observed_damage_value` 仅用于偏差展示；
   - 不写入战斗事件或实时估计 evidence。
3. `POST /api/v1/damage-calculator/infer-defender`
   - 根据敌方受击前后生命百分比进行一次性反推，后端自动计算扣血百分比；
   - `observed_damage_value` 必填，作为真实伤害严格校验信号；
   - 不再提供累计样本反推流程。

## 4. 单次反推逻辑

反推输入重点：

- `observed_hp_percent_before`：敌方受击前血量百分比；
- `observed_hp_percent_after`：敌方受击后血量百分比；
- `observed_hp_percent_delta`：兼容字段；前端常规不展示，优先通过受击前后百分比自动计算；
- `observed_damage_value`：真实伤害值，反推防御方配置时必填。

后端处理：

1. 常规场景用 `observed_hp_percent_before - observed_hp_percent_after` 得到扣血百分比；`observed_hp_percent_delta` 仅保留为兼容字段。
2. `modifiers.defender_hp_percent` 已弃用，独立计算器不再额外暴露目标血量上下文字段。
3. 先解析一次与候选面板无关的规则上下文，再枚举全部性格，减少重复查库和重复规则解析。
4. 默认枚举完整三维满资质配置：被培养维度均取 10，未培养维度为 0；物理技能用 HP / 物防参与伤害匹配，魔法技能用 HP / 魔防参与伤害匹配，但候选仍返回完整六维资质。
5. 对每个候选复用正向伤害公式，得到理论伤害值和 `理论伤害 / 候选最大 HP` 的扣血百分比。
6. 候选必须命中真实伤害；当玩家录入的是整数血量百分比时，理论扣血百分比按游戏显示规则向下取整后与 `受击前百分比 - 受击后百分比` 比较，例如理论扣血 `20.58%` 会匹配录入扣血 `20%`。若录入了小数百分比，则保留小范围容差比较。
7. 结果只展示满足观测约束的候选；若无候选满足，返回空列表，避免把明显不可能的配置排进结果。
8. 返回候选先按真实伤害/百分比综合误差排序；同等命中误差下，会复用《敌方默认配置性格与资质约定_v0.1.md》对应的默认性格与三维 10 资质作为偏好排序，再在 `top_n` 截断前保留每个正面性格类别的最优命中候选，避免多个等价配置因返回数量限制而被误解为“已排除”。

如果缺少真实伤害或受击前后血量百分比，普通攻击公式通常无法同时约束敌方 HP 资质和防御资质；因此前端反推模式要求两者都填写。

## 5. 前端交互

页面：`frontend/src/pages/DamageCalculatorPage.tsx`，路由 `/damage-calculator`。

主要区域：

1. 最近战斗快捷导入；
2. 攻击方配置卡；
3. 防御方配置卡；
4. 技能搜索与技能描述；
5. 状态类修正与公式覆盖；
6. 右侧“单纯计算伤害 / 反推防御方”模式切换；
7. 反推模式填写敌方受击前血量、受击后血量；扣血百分比由后端自动计算；
8. 防御方候选列表按正面性格分组（如物攻+、速度+、魔攻+）并支持展开/收起，默认全部收起；重点展示性格和三维资质，辅助展示预测伤害。

## 6. 状态类修正

前端常规输入使用战斗工作台已有的状态语义，而不是直接暴露底层倍率：

- 攻击方物攻增加/降低层数；
- 攻击方魔攻增加/降低层数；
- 防御方物防增加/降低层数；
- 防御方魔防增加/降低层数；
- 技能威力增加/降低层数；
- 连击次数；
- 自填技能威力。

换算约定：

- 属性增减每层按 10%；
- 技能威力每层按 10 点威力；
- 自填技能威力会覆盖技能定义中的基础威力，适合处理过曝等静态规则或技能槽历史修正尚未自动覆盖的情况；
- 物理技能读取物攻/物防层数；
- 魔法技能读取魔攻/魔防层数；
- 这些修正只进入独立计算器 payload，不写入战斗状态栏。

## 7. 风险与限制

- 反推结果依赖当前项目伤害公式和状态修正是否完整；若存在 `unknown_factors`，需要降低置信度。
- 百分比读数可能有 UI 显示误差；当前反推对整数扣血百分比按向下取整后的显示值匹配。若无候选应优先复核技能威力、状态、减伤、克制、本系和连击上下文。
- 当前不做累计样本反推，避免界面和解释链过重；如后续需要，应重新设计为单独模式。
