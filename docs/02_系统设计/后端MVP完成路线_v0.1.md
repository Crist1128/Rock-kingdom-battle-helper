# 后端 MVP 完成路线 v0.2

更新日期：2026-06-10

> 当前路线：实时面板估计、默认配置校验、事件 evidence、状态/天气公式上下文和事件流重放。旧候选空间、候选软评分、候选硬排除和 `/candidates/*` 已从当前实现中移除。

## 1. MVP 完成目标

后端 MVP 的完成标准不是覆盖所有游戏规则，而是形成一条可解释、可重放的本地战斗事实链：

1. 玩家可以录入战斗、阵容、技能、伤害、状态、资源和切换。
2. 伤害和状态结算基于事件发生时的状态快照解释，不读取已经变化的当前状态冒充历史状态。
3. Observation、手动伤害事件和自动结算伤害写入 `EnemyPanelEstimate` 与 `EnemyPanelEstimateEvidence`。
4. 实时估计能说明属性约束来源、unknown factors、冲突原因和置信状态。
5. 事件作废或修正后，可以从指定事件重放估计层和基础运行时状态。
6. 静态规则导入支持 dry-run、commit、摘要、错误列表和可回滚边界。

## 2. 已完成能力

- Alembic 迁移、SQLite 初始化和核心 ORM 已建立。
- rocom 静态数据管线已支持当前 BWIKI 精灵/技能页面、技能图鉴覆盖、全量刷新和缺六维保护。
- 旧 `build_candidate` / `calculation_cache` 表已由 `0006_drop_legacy_candidate_tables` 删除。
- 敌方阵容录入后会初始化 `EnemyPanelEstimate` 和默认展示配置。
- 默认配置可按当前实时约束校验并保存。
- Observation API 支持伤害值、扣血百分比、技能出现和速度先后手。
- 普通攻击最小公式、P0 状态伤害、星陨伤害、阶段 C 自动结算、阶段 D 技能效果操作执行器和阶段 E 最小减伤/应对解析已经接入。
- `EventReplayService` 已能重建实时估计/evidence，并重算切换、HP、能量、最终状态实例和事件后快照链。

## 3. 未完成能力

- 天气、状态、印记和技能槽 modifier 尚未完整接入实时反推。
- 完整应对/防御独立结算层仍需补齐。
- 速度约束目前以 observation/evidence 为主，尚未形成完整先后手概率解释。
- 自动结算副作用重放仍需扩展。
- Estimate evidence 还缺少面向公式上下文和冲突原因的完整解释页。
- 图像识别未开始。

## 4. 下一阶段顺序

### 阶段 F：实时估计解释增强（已完成基础闭环）

目标：让每条影响估计的事件都能解释清楚。

后端任务：

1. 扩展 `EnemyPanelEstimateEvidence` 的解释内容，记录公式上下文、关键倍率、状态快照 ID、受影响属性和 unknown factors。
2. 对普通攻击、状态伤害、星陨伤害统一输出 evidence 摘要。
3. 约束交集为空时记录 conflict，不自动覆盖玩家默认配置为不明来源值。

验收：

- 前端能看到“哪次事件导致 HP/防御/攻击约束变化”。
- 公式上下文不完整时只记录 unknown，不收窄属性范围。

当前落地：`EnemyPanelEstimateEvidence.explanation` 已返回来源事件、快照 ID、关键倍率、受影响属性、约束变化、未收窄原因、unknown factors 和冲突摘要；前端实时估计面板已展示约束变化、关键倍率、天气/状态 modifier、未收窄原因和冲突摘要。状态伤害、星陨和更多复杂公式仍按后续阶段继续补齐规则来源。

### 阶段 G：天气/状态 modifier 接入

目标：把天气、状态、印记、技能槽效果作为伤害公式和实时反推的上下文来源。

后端任务：

1. 从 `BattleEffectSnapshot.full_snapshot_json` 读取事件发生时状态。
2. `ModifierResolver` 汇总天气倍率、状态增减伤、防御技能减伤、应对倍率和特殊分支。
3. 输出结构化解释：来源、倍率、是否确定、未知因素。

验收：

- 天气/状态不完整时写入 unknown factors。
- 天气/状态明确时进入伤害公式和实时估计约束。

### 阶段 H：完整应对/防御结算层

目标：应对和防御不再只是伤害事件 payload，而是可解释的独立结算上下文。

后端任务：

1. 统一 `defense_skill_id`、`response_attack_success`、`response_defense_success`、`response_status_success` 的结算语义。
2. 区分应对成功、应对失败、未知应对三种情况。
3. 将防御技能和应对结果写入公式解释链。

验收：

- 应对成功时能稳定套用倍率或减伤。
- 应对未知时不强行收窄实时估计。

### 阶段 I：事件重放扩展

目标：事件修正后，状态实例和事件后快照链可从事件流重建，自动结算副作用可按规则重演。

后端任务：

1. 扩展 `EventReplayService`，重演状态实例施加、移除、叠层、清除和天气替换。
2. 重演自动结算副作用，包括状态伤害、资源变化和状态变化。
3. 重建快照链并报告成功、跳过、unknown 和冲突。

验收：

- 修改历史伤害后，后续实时估计和快照链可重建。
- 修改历史状态后，后续状态伤害解释随重放更新。
