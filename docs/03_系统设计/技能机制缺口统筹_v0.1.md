# 技能机制缺口统筹 v0.1

更新日期：2026-06-12

本文基于 `data/rocom/cleaned_20260609/skills.json` 全量 496 条技能人工审阅结果整理，用于把零散的 `future_hooks` / `structure_gaps` 合并成后续可逐类落地的机制清单。

配套执行能力审计见 `docs/03_系统设计/技能规则执行能力审计_v0.1.md`；前端规则库页也提供“规则能力审计”标签页，可实时查看当前数据库中哪些规则已有执行链、哪些仍只是接口。

## 3. 建议处理顺序

### P1：先补“状态定义缺失”

建议优先确认并补齐：

1. 萌化；
2. 减速印记；
3. 降灵印记；
4. 风起印记；
5. 龙噬印记；
6. 湿润；
7. 眩晕；
8. 蓄力/蓄电类印记。

这些状态一旦有定义，很多 `needs_review` 可以直接降为 `partial` 或 `structured`。

### P2：再补“战斗时序类机制”

建议合并处理：

- 迅捷/先手；
- 当前回合是否切换；
- 蓄力；
- 下次无需蓄力；
- 回合结束返场/脱离；
- 延迟到下回合的状态或资源变化。

这类机制会影响事件流、速度判断和回放，必须先设计统一事件语义。

### P3：再补“技能槽与技能组机制”

建议合并处理：

- 传动；
- 技能位于 1/3 号槽；
- 相邻技能槽修正；
- 技能跨精灵移动；
- 本场永久技能槽威力/费用/连击修正的复杂触发；
- 按携带技能组组成计算分支。

### P4：最后补“动态公式”

包括：

- 速度差威力；
- 防御差威力；
- 生命比例威力；
- 能量消耗威力；
- 中毒/冻结/印记层数威力；
- 技能总能耗/技能威力和；
- 体重公式。

体重、奉献、变形、复制仍按当前约定暂不实现，只保留接口。

## 4. 需要人工确认的问题

进入下一轮代码落地前，建议先确认以下问题：

1. **萌化**：每层具体影响是什么？是降低/增加能耗、威力，还是只作为其它技能的条件？
2. **减速印记 / 降灵印记 / 风起印记 / 龙噬印记**：它们是否有回合结算、切换清除、层数上限、可驱散规则？
3. **蓄力**：蓄力技能是否第一回合只蓄力、第二回合出手？蓄力中被攻击是否打断？“下次技能无需蓄力”持续到何时？
4. **迅捷**：迅捷是固定先手层级，还是速度比较前的优先级修正？能否与技能自身 `priority_modifier` 叠加？
5. **传动**：传动 1/2 是移动技能槽位置，还是把效果传给相邻技能槽？触发时机是使用后立即，还是回合结束？

## 5. 2026-06-12 机制回应后的首批落地

已阅读 `docs/03_系统设计/技能机制缺口回应.txt`，并先落地其中不需要继续追问、且不会引入伪公式的部分。

### 已确认口径

- 萌化：每层让可回退阶段精灵回退 1 个阶段；层数上限与该精灵阶段上限有关，可由玩家判断。当前先记录状态层数，种族值/面板回退暂不自动改写。
- 已确认印记：
  - 湿润印记：全技能能耗每层 `-1`。
  - 光合印记：回合结束每层获得 `1` 能量。
  - 攻击印记：全技能威力每层 `+10%`。
  - 萌化印记：新获得的属性类增益额外获得 `1` 层；不作用于印记、天气、技能槽增益。
  - 降灵印记：入场时每层失去 `1` 能量。
  - 风起印记：先手攻击时本次技能威力每层 `+20%`；条件 flag 已保留，完整先手链路待补。
  - 蓄势印记：全攻击技能威力每层 `+30%`，且能耗每层 `+1`。
  - 蓄电印记：攻击技能获得进发/迸发，本次威力每层 `+10`；迸发条件待统一。
  - 减速印记：速度每层 `-10`。
  - 龙噬印记：释放 3 能耗技能时获得双攻 `+30%`，可叠加。
- 蓄力：第一回合选择蓄力技能即扣能并进入蓄力准备；第二回合需要再次选择同一技能释放；不会被打断；切换下场会清除蓄力准备；“下次技能无需蓄力”持续到使用需要蓄力的技能或精灵下场。
- 迅捷：可由玩家自行录入，本轮不自动处理。
- 传动：暂不考虑。
- 迸发：初始首发首回合也算登场首回合；返场可重新获得迸发资格；触发时需要记录具体附加效果。
- 体重、速度差、防御差、生命比例、能耗、能量消耗公式：先不考虑，留接口。
- 脱离/返场/打断：语义已确认，但需要事件流和重放统一方案，本轮暂未自动执行。

### 本轮已落地

- 新增 11 条确认机制状态定义和 17 条技能规则确认补丁；当前已整合进正式总文件 `backend/app/seed/manual_skill_effect_definitions_all_20260612.json` 与 `backend/app/seed/manual_skill_rule_reviews_all_20260612.json`，历史分批源文件已从工作树移除。
- 后端支持技能修正倍率按层数叠加：例如攻击印记每层 `+10%`、蓄势印记每层 `+30%`。
- 后端支持回合末/入场非伤害资源变化：
  - 光合印记回合末回能；
  - 降灵印记入场扣能。
- 后端支持龙噬印记技能使用触发：使用有效 3 能耗技能后，对行动方施加双攻层数型增益。
- 条件类印记增加防误用保护：风起印记按“攻击技能”覆盖物理/魔法攻击，但必须有 `actor_moves_before_target` 条件旗标才进入威力计算；蓄电印记保留 `requires_burst`，未明确 `burst_triggered` / `burst_active` 前不会自动把迸发威力写进预览或公式。
- 入场资源变化已补测试覆盖：降灵印记会在对应阵营精灵切换上场时按层数扣除能量。
- 萌化印记监听已落地：当目标获得正向 `stat_modifier` 属性增益时额外 +1 层；印记、天气、技能槽增益不会被加层。
- 迸发资格与记录已落地基础闭环：`skill_use` 会在初始首发首回合或切换/返场当回合自动补 `burst_active` / `burst_triggered` 条件旗标；若本次确有 `requires_burst` 的技能修正，会额外写入 `effect_trigger` 事件，记录具体附加效果。
- 蓄力状态机已落地最小闭环：带 `charge_before_attack` / `charge_turn_mechanic` / `charge_then_apply_effects` hook 的技能第一次选择扣能并施加 `effect_charge_ready`，本次技能效果暂不执行；再次选择同一技能释放并清除蓄力准备。当前按“释放不重复扣能”处理，若后续实测确认第二次仍扣能再调整。
- 返场语义已接入切换事件：后端允许 `from_elf_id == to_elf_id` 的 `switch_elf`，并标记 `switch_mode = return_to_field`；该流程会执行切换清除并立即触发入场结算。
- 打断先按“只标记未执行”落地事件类型占位：新增 `action_interrupted` 事件展示名称，不自动删除或改写已录入事件。
- 下列技能已从缺口状态推进为可执行或部分可执行：打湿、潮汐、光合作用、主场优势、降灵、风起、蓄势待发、增程电池、速冻、冰蛋壳、龙威、退化、捧杀、赤子之心、撒娇、超级糖果、月光合奏。

### 仍未自动落地

- 萌化导致的种族值/面板回退：当前只记录状态层数，玩家仍需手动修正面板。
- 风起印记的先手条件自动判定。
- 蓄电印记以 `requires_burst` 接入基础迸发窗口，但“继承已发生过的迸发效果”等高级历史监听仍未实现。
- 蓄力期间受击改威力、蓄力状态下可用防御技能等高级蓄力分支仍未实现。
- 迅捷、传动、体重/速度差/防御差等特殊公式、脱离强制换人、打断计划落库的事件流自动化。
