# Rock PVP Helper 前后端接口文档

> 审阅范围：当前前后端 MVP、Observation API、实时面板估计与 RuleResolver 雏形。
>
> 后端基准地址：`http://127.0.0.1:8001/api/v1`
> 前端开发地址：`http://127.0.0.1:5173`  
> 前端默认 API 基址：`/api/v1`，通过 Vite proxy 转发到后端。

---

## 1. 当前系统接口总览

### 1.1 前端页面与后端接口关系

| 前端页面 | 路由 | 主要后端接口 |
|---|---|---|
| 己方配置 | `/builds` | `/elves`、`/elves/{elf_id}/skills`、`/natures`、`/player-builds`、`/team-presets` |
| 战斗首页 | `/` | `/battles`、`/battles/{battle_id}/archive` |
| 准备阶段 | `/preparation` | `/battles`、`/player-builds`、`/team-presets`、`/battles/{battle_id}/lineup`、`/battles/{battle_id}/start` |
| 战斗工作台 | `/battle` | `/battles/{battle_id}/state`、`/battles/{battle_id}/switch`、`/battles/{battle_id}/finish`、`/effects`、`/effects/instances`、`/battles/{battle_id}/damage-events`、`/battles/{battle_id}/resource-events`、`/observations/{battle_id}`、`/estimates/*` |
| 事件日志 | `/events` | `/battles/{battle_id}/timeline`、`/battles/{battle_id}/events`、`/battles/{battle_id}/events/{event_id}/void`、`/battles/{battle_id}/events/{event_id}/correct`、`/battles/{battle_id}/replay-from/{event_id}` |
| 规则库 | `/rules` | `/elves`、`/skills`、`/natures`、`/effects` |
| 设置 | `/settings` | `/health`、`/admin/battles/*` |

### 1.2 当前接口状态

| 模块 | 状态 | 说明 |
|---|---:|---|
| 静态规则查询 | 可用 | 精灵、技能、性格、状态定义均可查询。 |
| 己方配置 | 可用 | 支持创建、编辑、技能槽排序、软删除。 |
| 配队预设 | 可用 | 支持保存己方 6 配置配队和敌方热门精灵阵容，准备阶段可快速填充。 |
| 战斗管理 | 可用 | 支持创建、列表、准备阶段阵容、开始、切换、结束、归档、状态查询。 |
| 状态系统 | 可用 | 支持状态定义筛选、状态实例施加与移除。 |
| 伤害事件 | 可用 | 支持单次、动画多段总伤害、连击单段伤害与次数；创建事件本身仍以记录事实为主。 |
| 观察事件 / 实时估计 | 可用 | `POST /observations/{battle_id}` 支持伤害值、扣血百分比、技能出现、速度先后手等观测，更新实时估计约束和 evidence，不再写旧候选评分。 |
| 资源事件 | 可用 | 支持生命/能量手动变化记录。 |
| 候选配置 | 已下线 | `/candidates/*` 不再挂载；旧 `build_candidate` 表暂不删除，仅标记为后续迁移清理对象。 |
| 实时面板估计 | 可用 | 已有估计档案查询、默认配置设置、估计 evidence 查询和按需展开可能配置接口；Observation 会同步写入 evidence，并在普通攻击最小公式上下文完整时写入低置信 HP/攻防范围；复杂公式、天气/状态反推和重算接口尚未实现。 |
| 事件纠错/重放 | 部分可用 | 支持作废、创建修正事件；重放接口目前是占位，不做真实重算。 |
| 归档清理 | 可用 | 支持归档战斗 dry-run 预览与物理删除，受管理令牌保护。 |
| 数据更新 | 可用 | 支持 rocom 检查、远程同步、本地导入、任务查询，受管理令牌保护。 |
| 伤害公式/速度公式/反推约束 | 部分实现 | 已有普通攻击最小公式、RuleResolver 雏形和基础速度观测记录；完整状态/特殊公式、速度概率和天气/状态约束仍未实现。 |

## 2. 通用约定

### 2.1 请求头

普通接口：

```http
Content-Type: application/json
```

管理接口如 `/admin/data-updates/*`、`/admin/battles/*`：如果后端配置了 `ADMIN_UPDATE_TOKEN`，需要额外传：

```http
X-Admin-Token: <你的管理令牌>
```

如果 `.env` 中 `ADMIN_UPDATE_TOKEN` 为空，则当前实现不会强制校验令牌。

### 2.2 常见枚举

#### 阵营 `side`

| 值 | 含义 |
|---|---|
| `self` | 己方 |
| `enemy` | 敌方 |

#### 战斗阶段 `phase`

| 值 | 含义 |
|---|---|
| `preparation` | 准备阶段 |
| `battle` | 战斗中 |
| `finished` | 已结束 |
| `archived` | 已归档 |

#### 伤害显示类型 `damage_display_type`

| 值 | 含义 | 必填字段 |
|---|---|---|
| `single_damage` | 单次伤害 | `damage_value` |
| `visual_total_damage` | 动画多段但最终显示总伤害 | `final_total_damage_value` |
| `combo_repeated_damage` | 连击，每段相同且无总伤害 | `per_hit_damage_value`、`hit_count` |
| `special_damage` | 特殊结算伤害 | 当前未专门实现公式逻辑 |

#### 状态归属范围 `owner_scope`

| 值 | 含义 | 施加状态时需要字段 |
|---|---|---|
| `elf` | 挂在某只精灵身上 | `owner_side`、`owner_elf_id` |
| `side` | 挂在某一队伍侧 | `owner_side` |
| `field` | 全战场 | 可用默认 `field_id=main` |
| `skill_slot` | 某个技能槽 | `owner_skill_slot_id` |
| `turn` | 当前回合临时状态 | 按后续规则扩展 |

## 4. 静态规则接口

## 4.1 精灵接口

### 4.1.1 查询精灵列表

```http
GET /api/v1/elves?q=<关键词>&limit=50&offset=0
```

Query 参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---:|---:|---|
| `q` | string | 空 | 按 `elf_name` 模糊搜索 |
| `limit` | int | 50 | 1-500 |
| `offset` | int | 0 | 分页偏移 |

响应字段：

```ts
interface ElfDefinitionOut {
  elf_id: string;
  elf_name: string;
  avatar: string;
  element_types_json: string;
  base_hp_talent: number;
  base_physical_attack_talent: number;
  base_physical_defense_talent: number;
  base_magic_attack_talent: number;
  base_magic_defense_talent: number;
  base_speed_talent: number;
  data_version?: string | null;
}
```

前端调用：

```ts
api.elves.list({ q, limit, offset })
```

### 4.1.2 查询单只精灵

```http
GET /api/v1/elves/{elf_id}
```

前端调用：

```ts
api.elves.get(elfId)
```

### 4.1.3 查询精灵可学习技能

```http
GET /api/v1/elves/{elf_id}/skills?q=<关键词>&limit=100&offset=0
```

说明：返回指定精灵可学习技能池，并虚拟包含核心默认技能 `core_skill_focus_energy`（聚能）。聚能为状态技能，能耗 0，使用后通过结构化操作给行动方增加 5 点能量；该默认技能不需要为每只精灵批量写入 `elf_learnable_skill` 关联。

用途：己方配置页选择技能时，按当前精灵过滤技能池。

前端调用：

```ts
api.elves.skills(elfId, { q, limit, offset })
```

# 5. 己方配置接口

## 5.1 创建己方配置

```http
POST /api/v1/player-builds
```

请求体：

```json
{
  "elf_id": "rocom_elf_0001",
  "nature_id": "nature_xxx",
  "individual_talent_distribution": {
    "hp": 0,
    "physical_attack": 0,
    "physical_defense": 10,
    "magic_attack": 10,
    "magic_defense": 0,
    "speed": 10
  },
  "skill_ids": ["skill_a", "skill_b", "skill_c", "skill_d"],
  "build_name": "高速魔攻配置",
  "is_default": false,
  "notes": "备注"
}
```

校验规则：

| 字段 | 规则 |
|---|---|
| `individual_talent_distribution.*` | 0-10 |
| `skill_ids` | 最多 4 个，不能重复 |

说明：`individual_talent_distribution.*` 是玩家界面显示个体资质。后端重新计算面板属性时，会在计算层转换为 `有效个体资质 = 显示个体资质 × 6`，前端不需要也不应提交转换后的有效值。

响应字段：

```ts
interface PlayerElfBuildOut {
  build_id: string;
  build_name?: string | null;
  elf_id: string;
  elf_name?: string | null;
  avatar?: string | null;
  element_types_json?: string | null;
  nature_id: string;
  individual_talent_distribution_json: string;
  final_stats_json?: string | null;
  skill_ids: string[];
  is_default: boolean;
  notes?: string | null;
}
```

前端调用：

```ts
api.playerBuilds.create(payload)
```

## 5.2 查询己方配置列表

```http
GET /api/v1/player-builds?elf_id=<精灵ID>
```

`elf_id` 可选。不传则返回所有未软删除配置。

前端调用：

# 6. 配队预设接口

配队预设用于准备阶段快速填充阵容。己方配队由已保存的 `PlayerElfBuild`
组成，必须提供 `build_id`；敌方热门阵容用于快速录入敌方精灵种类，可以
只保存 `elf_id`。

## 6.1 创建配队预设

```http
POST /api/v1/team-presets
```

请求体：

```json
{
  "preset_name": "常用火神队",
  "side_usage": "self",
  "source_type": "custom",
  "notes": "准备阶段快速填充己方阵容",
  "slots": [
    {
      "slot_index": 0,
      "elf_id": "rocom_elf_0001",
      "build_id": "build_xxx"
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `side_usage` | `self`、`enemy` 或 `both` |
| `source_type` | `custom` 或 `popular` |
| `slots[*].slot_index` | 0-5 |
| `slots[*].elf_id` | 精灵 ID |
| `slots[*].build_id` | 己方配队必填；敌方热门阵容可为空 |

响应字段：

```ts
interface TeamPresetOut {
  preset_id: string;
  preset_name: string;
  side_usage: "self" | "enemy" | "both";
  source_type: "custom" | "popular";
  notes?: string | null;
  slots: TeamPresetSlotOut[];
  created_at?: string | null;
  updated_at?: string | null;
}

interface TeamPresetSlotOut {
  slot_id: string;
  preset_id: string;
  slot_index: number;
  elf_id: string;
  elf_name?: string | null;
  avatar?: string | null;
  element_types_json?: string | null;
  build_id?: string | null;
  build_name?: string | null;
  notes?: string | null;
}
```

前端调用：

```ts
api.teamPresets.create(payload)
```

## 6.2 查询配队预设列表

```http
GET /api/v1/team-presets?side_usage=self&source_type=custom
```

`side_usage` 与 `source_type` 均可选。按 `side_usage=self` 查询时会同时返回
`both`；按 `side_usage=enemy` 查询时也会同时返回 `both`。

前端调用：

```ts
api.teamPresets.list({ side_usage: "self" })
api.teamPresets.list({ side_usage: "enemy", source_type: "popular" })
```

## 6.3 查询单个配队预设

```http
GET /api/v1/team-presets/{preset_id}
```

前端调用：

```ts
api.teamPresets.get(presetId)
```

## 6.4 更新配队预设

```http

```

请求体同创建配队。当前采用整单替换槽位。

前端调用：

```ts

```

## 6.5 删除配队预设

## 7.4 录入双方阵容

```http
POST /api/v1/battles/{battle_id}/lineup
```

请求体：

```json
{
  "elves": [
    {
      "side": "self",
      "elf_id": "rocom_elf_0001",
      "build_id": "build_xxx",
      "is_active_elf": true
    },
    {
      "side": "enemy",
      "elf_id": "rocom_elf_0100",
      "build_id": null,
      "is_active_elf": true
    }
  ]
}
```

规则：

| 规则 | 当前行为 |
|---|---|
| 己方精灵 | 必须提供 `build_id` |
| 敌方精灵 | 只需要 `elf_id`，不需要资质、性格、技能配置 |
| 数量 | 每方最多 6 只，不强制必须 6 只 |
| 首发 | 每方最多 1 只首发 |
| 实时估计 | 敌方精灵会自动创建实时面板估计档案 |
| 旧候选 | 不再默认生成，`/candidates/*` 已删除；旧表仅等待后续迁移清理 |
| 阶段 | 正常只应在 `preparation` 阶段录入 |

运行时初始状态：

- 双方所有录入精灵的初始能量 `energy = 10`。


> 当前状态：第一阶段已实现估计档案表、阵容录入初始化、自动默认配置、查询接口、默认配置设置接口、evidence 查询接口、按需展开可能配置接口、Observation evidence 写入和普通攻击最小公式反向约束。复杂公式、天气/状态反推和重算接口仍按新实时反推方案继续实现。

实时面板估计已经替代“准备阶段全量生成候选 + Observation 逐候选写分”的默认主流程。敌方精灵默认保存一个估计档案，包含玩家选择的默认配置、当前估计面板、HP/物防/魔防/物攻/魔攻/速度约束、unknown factors 和 evidence 摘要。需要查看可能配置时，通过实时展开接口在内存中计算，不写旧候选表。

## 12A.1 查询敌方面板估计

```http
GET /api/v1/estimates/{battle_id}/{elf_id}
```

用途：查询某场战斗中某只敌方精灵的当前估计档案。若战斗阵容中存在该敌方精灵但估计档案缺失，后端会补建估计档案并按种族值启发式生成默认配置：物攻高于魔攻且速度低于 115 时默认加物攻减魔攻并点生命/物攻/速度；魔攻更高时对应加魔攻；速度大于等于 115 时默认加速度，负面项压低非主攻。

计划响应核心字段：

```ts
interface EnemyPanelEstimateOut {
  estimate_id: string;
  battle_id: string;
  elf_id: string;
  default_config?: Record<string, unknown> | null;
  default_panel?: Record<string, number> | null;
  estimated_panel?: Record<string, unknown> | null;
  stat_constraints: Record<string, unknown>;
  confidence: Record<string, unknown>;
  unknown_factors: string[];
  confirmed_skill_ids: string[];
  evidence_summary: Record<string, unknown>[];
  updated_by_event_id?: string | null;
}
```

## 12A.2 设置默认配置

```http
PUT /api/v1/estimates/{battle_id}/{elf_id}/default-config
```

用途：保存玩家选择的默认配置方案，用于真实面板未知时的临时展示。保存时会用当前实时推导的整数约束校验面板；若已经推导出某性格/资质不可能成立，后端会拒绝保存。默认配置只影响展示，不作为排除其它配置的依据。

计划请求示例：

```json
{
  "preset": "speed",
  "nature_id": "speed_plus_physical_attack_minus",
  "individual_talent_distribution": {
    "hp": 0,
    "physical_attack": 0,
    "physical_defense": 9,
    "magic_attack": 10,
    "magic_defense": 0,
    "speed": 10
  }
}
```

## 12A.3 查询估计 evidence

```http
GET /api/v1/estimates/{battle_id}/{elf_id}/evidence
```

用途：查询实时估计变化的事件级解释链，包括来源事件、推导属性、约束变化、公式上下文、unknown factors 和冲突说明。当前 Observation 已会写入 evidence；普通攻击最小公式上下文完整时，`inferred_stats` 会包含低置信 HP/攻防范围。上下文不足或公式类型尚未支持时，仍只记录 pending 约束和 unknown factors。

## 12A.4 重算估计档案

```http
POST /api/v1/estimates/{battle_id}/{elf_id}/recompute
```

计划用途：从事件流重新构建估计档案。该接口依赖后续事件重放重算能力，当前尚未实现。

## 12A.5 Observation 行为

`POST /api/v1/observations/{battle_id}` 现在固定更新实时面板估计。旧候选软评分不再作为可选模式提供，`allow_hard_exclude` 仅保留为废弃兼容字段。

# 13. 管理接口：归档战斗物理清理

> 这些接口是危险操作接口。默认建议只通过前端设置页触发，并先 dry-run 预览。


响应：

```ts

  battle_id: string;
  battle_name?: string | null;
  phase?: string | null;

```

```ts

```

## 13.2 物理删除单场归档战斗

```http
DELETE /api/v1/admin/battles/{battle_id}/purge?dry_run=true
X-Admin-Token: <可选>
```

Query 参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---:|---:|---|
| `dry_run` | bool | true | true 只预览；false 真实删除 |

安全规则：

- 只允许删除 `phase=archived` 或已软删除的战斗。
- `preparation` / `battle` / `finished` 不能直接物理删除。

响应：

```ts
interface BattlePurgeResultOut {
  dry_run: boolean;
  battle_count: number;
  battle_ids: string[];
  rows: Record<string, number>;
  message: string;
}
```

前端调用：

```ts
api.adminBattles.purgeBattle(battleId, { dry_run }, adminToken)
```

## 13.3 批量清理归档战斗

```http
DELETE /api/v1/admin/battles/purge-archived?dry_run=true&older_than_days=7&limit=50
X-Admin-Token: <可选>
```

Query 参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---:|---:|---|
| `dry_run` | bool | true | true 只预览；false 真实删除 |
| `older_than_days` | int/null | null | 只清理更新时间早于 N 天的归档战斗 |
| `limit` | int/null | null | 最多清理多少场，1-500 |

前端调用：

```ts
api.adminBattles.purgeArchived({ dry_run, older_than_days, limit }, adminToken)
```

## 16.4 空库与状态定义数据约定

空库初始化当前拆成三层：

1. **结构层**：只由 Alembic 负责，执行 `python -m alembic upgrade head`。
2. **核心性格层**：后端启动时自动幂等自检查并写入/修正 30 种性格；该流程只处理 `nature_definition`。
3. **外部静态规则层**：精灵、技能、可学习技能、属性克制等 rocom 数据，通过 rocom 数据管线 dry-run 后再提交。

# 18. 常见错误码说明

| 状态码 | 常见原因 |
|---:|---|
| 400 | 请求字段不满足业务规则，如己方阵容缺少 `build_id`、伤害类型缺少必填伤害字段、尝试物理删除未归档战斗。 |
| 403 | 管理接口令牌错误，`X-Admin-Token` 与 `ADMIN_UPDATE_TOKEN` 不匹配。 |
| 404 | 资源不存在，如 `battle_id`、`elf_id`、`skill_id`、`snapshot_id` 不存在，或已被物理删除。 |
| 409 | 数据更新任务已有运行中的任务，暂不接受新任务。 |
| 422 | JSON 格式或 Pydantic 字段类型校验失败。 |
| 502 | rocom 远程检查失败，通常是 BWIKI 网络或页面变化。 |
