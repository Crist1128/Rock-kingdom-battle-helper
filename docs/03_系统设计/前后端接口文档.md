# Rock PVP Helper 前后端接口文档

> 审阅范围：当前前后端 MVP、Observation API、实时面板估计与 RuleResolver 雏形。
>
> 后端基准地址：`http://127.0.0.1:8001/api/v1`
> 前端开发地址：`http://127.0.0.1:5173`  
> 前端默认 API 基址：`/api/v1`，通过 Vite proxy 转发到后端。

---

## 1. 当前系统接口总览

### 1.1 前端页面与后端接口关系

| 前端页面 | 路由 | 主要后端接口 |
|---|---|---|
| 己方配置 | `/builds` | `/elves`、`/elves/{elf_id}/skills`、`/natures`、`/player-builds`、`/team-presets` |
| 战斗首页 | `/` | `/battles`、`/battles/{battle_id}/archive` |
| 准备阶段 | `/preparation` | `/battles`、`/player-builds`、`/team-presets`、`/battles/{battle_id}/lineup`、`/battles/{battle_id}/start` |
| 战斗工作台 | `/battle` | `/battles/{battle_id}/state`、`/battles/{battle_id}/switch`、`/battles/{battle_id}/finish`、`/effects`、`/effects/instances`、`/battles/{battle_id}/damage-events`、`/battles/{battle_id}/resource-events`、`/observations/{battle_id}`、`/estimates/*` |
| 事件日志 | `/events` | `/battles/{battle_id}/timeline`、`/battles/{battle_id}/events`、`/battles/{battle_id}/events/{event_id}/void`、`/battles/{battle_id}/events/{event_id}/correct`、`/battles/{battle_id}/replay-from/{event_id}` |
| 规则库 | `/rules` | `/elves`、`/skills`、`/skills/review`、`/skills/capability-audit`、`/skills/{skill_id}/rules`、`/natures`、`/effects` |
| 设置 | `/settings` | `/health`、`/admin/battles/*` |

### 1.2 当前接口状态

| 模块 | 状态 | 说明 |
|---|---:|---|
| 静态规则查询/维护 | 可用 | 精灵、技能、性格、状态定义均可查询；技能规则可通过人工维护入口逐条补齐。 |
| 己方配置 | 可用 | 支持创建、编辑、技能槽排序、软删除。 |
| 配队预设 | 可用 | 支持保存己方 6 配置配队和敌方热门精灵阵容，准备阶段可快速填充。 |
| 战斗管理 | 可用 | 支持创建、列表、准备阶段阵容、开始、切换、结束、归档、状态查询。 |
| 状态系统 | 可用 | 支持状态定义筛选、状态实例施加与移除。 |
| 伤害事件 | 可用 | 支持单次、动画多段总伤害、连击单段伤害与次数；创建事件本身仍以记录事实为主。 |
| 观察事件 / 实时估计 | 可用 | `POST /observations/{battle_id}` 支持伤害值、扣血百分比、技能出现、速度先后手等观测，更新实时估计约束和 evidence。 |
| 资源事件 | 可用 | 支持生命/能量手动变化记录。 |
| 旧候选配置 | 已删除 | `/candidates/*`、旧候选代码和旧候选表结构均不再保留。 |
| 实时面板估计 | 可用 | 已有估计档案查询、默认配置设置、估计 evidence 查询；Observation 会同步写入 evidence，并在普通攻击最小公式上下文完整时写入低置信 HP/攻防范围；evidence 已返回最小解释结构和天气/状态 modifier 概览，复杂技能规则仍需扩展。 |
| 事件纠错/重放 | 部分可用 | 支持作废、创建修正事件；重放接口已可重建实时估计/evidence，并按非作废事件流重算基础运行时状态（切换、HP、能量）、最终状态实例和事件后快照链。自动结算副作用仍未完整重演。 |
| 归档清理 | 可用 | 支持归档战斗 dry-run 预览与物理删除，受管理令牌保护。 |
| 数据更新 | 可用 | 支持 rocom 检查、远程同步、本地导入、任务查询，受管理令牌保护。 |
| 伤害公式/速度公式/反推约束 | 部分实现 | 已有普通攻击最小公式、RuleResolver 雏形和基础速度观测记录；完整状态/特殊公式、速度概率和天气/状态约束仍未实现。 |

## 2. 通用约定

### 2.1 请求头

普通接口：

```http
Content-Type: application/json
```

管理接口如 `/admin/data-updates/*`、`/admin/battles/*`：如果后端配置了 `ADMIN_UPDATE_TOKEN`，需要额外传：

```http
X-Admin-Token: <你的管理令牌>
```

如果 `.env` 中 `ADMIN_UPDATE_TOKEN` 为空，则当前实现不会强制校验令牌。

### 2.2 常见枚举

#### 阵营 `side`

| 值 | 含义 |
|---|---|
| `self` | 己方 |
| `enemy` | 敌方 |

#### 战斗阶段 `phase`

| 值 | 含义 |
|---|---|
| `preparation` | 准备阶段 |
| `battle` | 战斗中 |
| `finished` | 已结束 |
| `archived` | 已归档 |

#### 伤害显示类型 `damage_display_type`

| 值 | 含义 | 必填字段 |
|---|---|---|
| `single_damage` | 单次伤害 | `damage_value` |
| `visual_total_damage` | 动画多段但最终显示总伤害 | `final_total_damage_value` |
| `combo_repeated_damage` | 连击，每段相同且无总伤害 | `per_hit_damage_value`、`hit_count` |
| `special_damage` | 特殊结算伤害 | 当前未专门实现公式逻辑 |

#### 状态归属范围 `owner_scope`

| 值 | 含义 | 施加状态时需要字段 |
|---|---|---|
| `elf` | 挂在某只精灵身上 | `owner_side`、`owner_elf_id` |
| `side` | 挂在某一队伍侧 | `owner_side` |
| `field` | 全战场 | 可用默认 `field_id=main` |
| `skill_slot` | 某个技能槽 | `owner_skill_slot_id` |
| `turn` | 当前回合临时状态 | 按后续规则扩展 |


### 4.1.3 查询精灵可学习技能

```http
GET /api/v1/elves/{elf_id}/skills?q=<关键词>&limit=100&offset=0
```

说明：返回指定精灵可学习技能池，并虚拟包含核心默认技能 `core_skill_focus_energy`（聚能）。聚能为状态技能，能耗 0，使用后通过结构化操作给行动方增加 5 点能量；该默认技能不需要为每只精灵批量写入 `elf_learnable_skill` 关联。

用途：己方配置页选择技能时，按当前精灵过滤技能池。

前端调用：

```ts
api.elves.skills(elfId, { q, limit, offset })
```

### 4.2.3 查询技能规则审阅队列

```http

```

用途：从当前数据库逐条审阅技能，筛选尚未结构化、待确认或模糊保留的技能。审阅状态不单独建表，当前写入 `damage_rule_json.manual_review` 元数据；明确规则仍写入 `damage_rule_json`、`hit_rule_json`、`effect_operations_json`。

| 参数 | 类型 | 默认 | 说明 |

```ts
interface SkillRuleReviewOut extends SkillDefinitionOut {

  review_notes?: string | null;
  has_damage_rule: boolean;
  has_hit_rule: boolean;
  has_effect_operations: boolean;
  rule_source: string;
}
```

前端调用：

```ts
api.skills.review({ q, review_status, limit, offset })
```

### 4.2.4 技能规则能力审计


```ts
  tested: boolean;

  notes?: string | null;
}

interface SkillRuleCapabilityAuditOut {

  supported_future_hook_counts: Record<string, number>;
```

### 4.2.5 手动维护技能规则

```http
PUT /api/v1/skills/{skill_id}/rules
X-Admin-Token: <可选，取决于后端 ADMIN_UPDATE_TOKEN>
```

用途：人工录入已经确认的技能伤害/应对规则、命中/连击规则和结构化效果操作。若技能描述模糊，不应写入可执行规则字段；只设置 `review_status = "needs_review"` 或 `"ambiguous"` 并填写 `review_notes`。

请求：

```ts
interface SkillRuleManualUpdate {
  damage_rule?: Record<string, unknown> | null;
  hit_rule?: Record<string, unknown> | null;
  effect_operations?: Record<string, unknown>[] | null;
  review_status?: "unreviewed" | "structured" | "partial" | "needs_review" | "ambiguous";
  review_notes?: string | null;
}
```

说明：

- 未传字段保持原值；显式传 `null` 会清空对应 JSON 字段。
- `damage_rule` 必须是 JSON 对象，适合保存 `defense_modifier`、`response_rule`、特殊伤害规则等。
- `effect_operations` 必须是 JSON 对象数组，供 `EffectOperationExecutor` 在 `skill_use` 时执行。
- 后端会把审阅状态写入 `damage_rule_json.manual_review`，但 `ModifierResolver` 只消费明确的规则字段，不会把 `manual_review` 当成伤害公式。

前端调用：

```ts
api.skills.updateRules(skillId, payload, adminToken)
```

# 5. 己方配置接口

## 5.1 创建己方配置

```http
POST /api/v1/player-builds
```

请求体：

```json
{
  "elf_id": "rocom_elf_0001",
  "nature_id": "nature_xxx",
  "individual_talent_distribution": {
    "hp": 0,
    "physical_attack": 0,
    "physical_defense": 10,
    "magic_attack": 10,
    "magic_defense": 0,
    "speed": 10
  },
  "skill_ids": ["skill_a", "skill_b", "skill_c", "skill_d"],
  "build_name": "高速魔攻配置",
  "is_default": false,
  "notes": "备注"
}
```

校验规则：

| 字段 | 规则 |
|---|---|
| `individual_talent_distribution.*` | 0-10 |
| `skill_ids` | 最多 4 个，不能重复 |

说明：`individual_talent_distribution.*` 是玩家界面显示个体资质。后端重新计算面板属性时，会在计算层转换为 `有效个体资质 = 显示个体资质 × 6`，前端不需要也不应提交转换后的有效值。

响应字段：

```ts
interface PlayerElfBuildOut {
  build_id: string;
  build_name?: string | null;
  elf_id: string;
  elf_name?: string | null;
  avatar?: string | null;
  element_types_json?: string | null;
  nature_id: string;
  individual_talent_distribution_json: string;
  final_stats_json?: string | null;
  skill_ids: string[];
  is_default: boolean;
  notes?: string | null;
}
```

前端调用：

```ts
api.playerBuilds.create(payload)
```

# 6. 配队预设接口

配队预设用于准备阶段快速填充阵容。己方配队由已保存的 `PlayerElfBuild`
组成，必须提供 `build_id`；敌方热门阵容用于快速录入敌方精灵种类，可以
只保存 `elf_id`。

## 6.1 创建配队预设

```http
POST /api/v1/team-presets
```

请求体：

```json
{
  "preset_name": "常用火神队",
  "side_usage": "self",
  "source_type": "custom",
  "notes": "准备阶段快速填充己方阵容",
  "slots": [
    {
      "slot_index": 0,
      "elf_id": "rocom_elf_0001",
      "build_id": "build_xxx"
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `side_usage` | `self`、`enemy` 或 `both` |
| `source_type` | `custom` 或 `popular` |
| `slots[*].slot_index` | 0-5 |
| `slots[*].elf_id` | 精灵 ID |
| `slots[*].build_id` | 己方配队必填；敌方热门阵容可为空 |

响应字段：

```ts
interface TeamPresetOut {
  preset_id: string;
  preset_name: string;
  side_usage: "self" | "enemy" | "both";
  source_type: "custom" | "popular";
  notes?: string | null;
  slots: TeamPresetSlotOut[];
  created_at?: string | null;
  updated_at?: string | null;
}

interface TeamPresetSlotOut {
  slot_id: string;
  preset_id: string;
  slot_index: number;
```

- 伤害事件接口会记录手动伤害事实、生成快照并返回事件结果。
- 敌方受击时通常只知道百分比，可继续传 `hp_percent_before` / `hp_percent_after`；我方受击时只需传准确 `damage_value`，后端会基于当前精确 HP 扣减，并自动写入 `ResourceChangeEvent(value)` 的前后值。`hp_value_before` / `hp_value_after` 仍作为兼容字段保留给手动纠错或显式覆盖。
- `defense_skill_id` 和 `response_attack_success` / `response_defense_success` / `response_status_success` 为可选字段；存在时会进入 `BattleEvent.payload_json` 和 `DamageEvent.formula_context_json`，并触发 RuleResolver 解析防御技能减伤与应对分支。
- `condition_flags` 为可选通用条件标记，支持 `actor_moves_before_target`、`actor_moves_after_target`、`target_switched_this_turn`、`post_damage_defeat_condition` 等布尔值。后端会合并手动标记和同回合切换推断结果，并平铺给 RuleResolver；未提供的条件保持未知，不按 false 硬判。
- 当攻击技能自己的 `damage_rule_json.response_rule` 存在时，RuleResolver 会自动装载该应对分支；`modifier="power_multiplier"` 会写入 `power_multiplier`，缺少成功标记时只记录 `response_success_unknown`。
- 这些字段当前不新增独立数据库列；历史解释以事件 payload、公式上下文和快照为准。
- 阶段 C 起，接口会在手动伤害后尝试执行 P0 攻击后结算；当前支持星陨印记。
- 若星陨上下文完整，会额外生成系统来源的 `DamageEvent`、`ResourceChangeEvent`、`EffectChangeEvent` 和快照，并在 `post_settlement_events` 返回摘要。
- 自动结算生成的伤害若目标是敌方，会在同一事务内转成 `damage_value` Observation，写入实时估计 evidence。
- 上下文不足或公式不适用时，后端仍可能返回 `formula_unavailable` / `not_triggered` / unknown，并不会假造伤害。


- 当前已落地的基础规则包括：雨天水系攻击 `weather_multiplier = 1.75`、暴风雪天气识别但不直接修改攻击伤害、力量增效施加物攻 +100% 状态、基础防御技能“防御”通过 `defense_skill_id` 读取 70% 减伤。

## 12A.4 重算估计档案

```http
POST /api/v1/estimates/{battle_id}/{elf_id}/recompute
```

已由 `POST /api/v1/battles/{battle_id}/replay-from/{event_id}` 承担估计层重建；
不再单独提供该 estimate 级 recompute 入口。后续若需要单精灵局部重算，再新增专用接口。

## 12A.5 Observation 行为

`POST /api/v1/observations/{battle_id}` 现在固定更新实时面板估计。

## 运行时有效形态/退化接口（2026-06-12）

### POST `/api/v1/battles/{battle_id}/elves/{state_id}/runtime-form`

用于手动处理退化、萌化面板回退等“战斗中按另一只精灵种族值结算”的情况。该接口不会调用普通切换逻辑，因此不会触发 `clear_on_switch`、返场、入场结算或首回合机制。

请求体：

```json
{
  "effective_elf_id": "目标有效形态精灵ID；null 表示恢复原始形态",
  "hp_policy": "keep_percent",
  "reason": "manual_runtime_form_change",
  "notes": "可选备注"
}
```

行为约定：

- `BattleElfState.elf_id` 保持原始精灵身份不变。
- `runtime_form_elf_id` 记录当前有效形态；为空时使用原始形态。
- 面板按“有效形态种族值 + 原性格 + 原个体培养”重算。
- 当前生命默认保留百分比，并按新最大 HP 向下折算当前 HP 值。
- 响应返回完整 `BattleStateOut`，`elves` 中额外包含 `effective_elf_id/effective_elf_name/effective_form_source` 等字段。
