# Rock PVP Helper

洛克王国世界 PVP 战斗信息获取、手动战斗记录、状态快照、伤害计算与敌方配置估计工具。

> 当前更新：2026-07-19
>
> 当前阶段：前后端可联调的手动输入 MVP 已成型，主流程已从旧候选空间切换到“实时面板估计 + evidence 解释链”。已补齐双重抵抗按四倍免伤（仅受 1/4 伤害）、双倍克制仍为 3 倍伤害的统一规则；新增精灵进化链静态表、seed 导入和设置页单独录入口，战斗工作台可按当前精灵进化链切换可进化/退化形态，并保留性格、资质与培养设置。本轮清理了未接入的第三方识图资料，准备页敌方头像识别已直接切换到透明模板库原型；当前仍只做候选确认，相关工作区改动暂不提交。当前重点仍是继续补齐复杂技能分支、天气/状态 modifier、完整应对/防御结算和速度判断。事件重放入口暂时在前端隐藏，后端能力保留给后续阶段恢复。

## 项目目标

本项目用于辅助记录和分析洛克王国世界 PVP 对局：

- 录入己方配置、敌方阵容、首发、切换、技能、伤害、资源和状态事件；
- 基于事件流生成状态快照，保证战斗过程可追溯、可重放；
- 使用静态规则、状态规则、技能分支和伤害公式估算理论伤害；
- 将 Observation、手动伤害事件和自动结算写入实时估计 evidence，用于推算敌方默认配置与可能面板；
- 提供独立于战斗工作台的伤害计算器，支持手动选择攻防双方、技能、性格资质、状态修正和扣血百分比反推；
- 为后续图像识别、自动识别头像/状态/技能信息预留数据与流程基础。

本仓库仍处于开发阶段，伤害公式、状态结算和复杂技能规则会持续校正。涉及未确认机制时，系统应保留 `unknown_factors` 或低置信说明，避免用伪公式硬排除候选。

## 当前进度概览

### 已完成 / 已可用

- **基础架构**
  - FastAPI + SQLAlchemy + SQLite + Alembic 后端。
  - React + TypeScript + Vite 前端。
  - 前后端已可本地联调。
- **静态数据管线**
  - 支持洛克王国世界 BWIKI 数据爬取、清洗、dry-run 和导入。
  - 已覆盖精灵、技能、可学习技能、属性克制等基础数据。
  - 技能定义已新增 `raw_description`，前端规则库和工作台技能卡优先展示中文原文描述。
  - 设置页已提供“新用户 / 空库一键初始化”，可检查必要数据、从本地 cleaned 包 dry-run/提交初始化，并显示后台任务进度条。
  - 新增 `elf_evolution_chain` / `elf_evolution_stage` 独立进化链静态表、Alembic 迁移、seed 数据和 dry-run/commit 导入入口；已有基础精灵数据的旧库可在设置页单独录入进化链规则。
- **手动战斗 MVP**
  - 支持战斗创建、阵容录入、首发确认、切换、伤害事件、资源事件、状态事件、技能事件、时间线和快照。
  - 准备阶段已补充必做项校验，缺漏时前端会提示。
  - 战斗工作台支持运行时有效形态切换：优先展示当前精灵进化链内可进化/退化形态，切换后对位卡、队伍头像和名称按有效形态展示，但原始精灵身份、性格、资质与培养保持不变。
- **实时面板估计**
  - 敌方精灵会生成实时估计档案。
  - Observation、手动伤害和自动结算伤害会写入 evidence。
  - 默认配置性格与资质规则已落地，可按当前约束更新敌方默认面板。
- **伤害与规则解析**
  - 已接入基础 PVP 面板公式、普通攻击最小公式、属性克制、本系加成、部分天气/状态 modifier、应对减伤解析。
  - 属性克制聚合已统一为：双重抵抗按四倍免伤（0.25 倍受伤），双倍克制仍按 3 倍伤害；伤害计算器、实时估计与规则解释链共用该口径。
  - 连击计算已接入：静态规则可预填，用户手动填写连击次数优先。
  - 中英文属性别名已统一匹配，避免 `火` / `fire`、`草` / `grass` 等 seed 与 rocom 数据不一致导致规则不生效。
- **独立伤害计算器**
  - 新增侧边栏入口“伤害计算器”，可不创建战斗、不写入事件、不污染实时估计 evidence。
  - 支持从最近战斗和已保存己方配置快捷导入，也支持现场搜索攻防双方精灵、选择技能、性格与资质模板。
  - 支持本系/克制倍率预填、天气/减伤/连击/技能威力层数和物攻/魔攻/物防/魔防层数等状态类修正。

- **状态与技能效果**
  - 已落地状态定义、层数状态、部分回合末/入场/切换结算。
  - `EffectOperationExecutor` 已支持多类结构化技能操作。
  - 设置页已提供项目静态规则同步检查入口，可同时检查/同步状态定义与 structured 技能规则，支持 dry-run 后由用户确认写库。
  - 已新增“技能使用次数”状态口径：精灵侧 1 层表示该精灵下次使用任意技能时等效多使用 1 次，并参与能耗与理论总伤害展示；另保留“本技能使用次数增加”用于明确写明本技能永久变化的技能槽修正。

### 后端

```powershell

python -m pip install -e ".[dev]"

python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001 --access-log --log-level info
```

```powershell
cd frontend
npm.cmd install --no-audit --no-fund

```

前端地址：

```text
http://127.0.0.1:5173
```

### 新用户 / 空库数据初始化

空库电脑首次使用前需要准备的数据分为四类：

1. **数据库结构**：后端启动或 `init_db` 会通过 Alembic 自动迁移。
2. **核心规则**：30 种核心性格和默认通用技能“聚能”，后端启动会幂等补齐。
3. **BWIKI 静态数据**：精灵、技能、可学习技能、属性克制，来自 `data/rocom/cleaned` 或远程 BWIKI 爬取。
4. **项目规则 seed**：状态定义和人工技能分支，位于 `backend/app/seed/*.json`，会随本地/远程导入并入同一事务。

推荐新用户走前端：

1. 启动后端和前端。
2. 打开 `设置 / 数据管理`。
3. 查看“新用户 / 空库一键初始化”的数据状态。
4. 先点 dry-run 预检查，再点“一键初始化本地数据库”。

该入口使用后台任务，前端会轮询并显示进度条；如果本地 `data/rocom/cleaned` 缺失，再使用远程 BWIKI 同步。

### 本地 cleaned 数据包

如果已有可用的 cleaned JSON，可打包成 zip 发给新用户，避免每台电脑重新爬取：

```powershell
python scripts/package_rocom_cleaned_data.py --output data/packages/rocom_cleaned_YYYYMMDD.zip
```

数据包只包含：

- `elves.json`
- `skills.json`
- `elf_learnable_skills.json`
- `type_effectiveness_rules.json`
- `import_summary.json`（如存在）

新用户解压后放到 `data/rocom/cleaned/`，再走设置页“一键初始化”。不要直接分发 `data/app.db`，避免把本机战斗记录、缓存或未来的个人数据一起带出去。

### 命令行导入建议

涉及规则 seed、BWIKI cleaned 数据或批量更新时，仍然优先先 dry-run，再显式 commit。前端设置页已经覆盖常用的一键初始化、本地导入和远程同步；命令行导入主要用于调试或批量维护。

## 重要开发原则

- 事件流稳定优先，历史解释应基于事件发生时的快照。
- 规则导入、批量更新和清理必须优先 dry-run。
- 未确认的伤害、速度或技能机制不要写成硬公式，应保留 unknown factors 或低置信说明。
- 前后端接口变更要同步 schema、类型和接口文档。
- 中文文档和 seed 文件应保持 UTF-8，避免乱码和连续问号占位。
